# 실차 통합 RULE 주행 튜닝

이 문서는 현재 실차 통합 주행을 실행하고 Pure Pursuit·Stanley 제어값을
반복 시험하기 위한 기준이다. 기본 우선순위는 `콘 > 차량 회피 > RULE`이며
신호등 주행은 아직 활성화하지 않는다.

## 인지 지연 개선

고속 주행에서 오래된 카메라 프레임으로 조향하는 문제를 줄이기 위해 다음을
적용했다.

- 1280x1024 영상을 전부 보정한 뒤 다시 축소하지 않고, 카메라 보정 맵으로
  모델 입력 크기에 직접 remap한다.
- 보정 결과가 이미 모델 크기라면 추론 직전의 중복 resize를 생략한다.
- 입력 큐를 쌓지 않고 가장 최신 프레임만 처리하는 latest-frame scheduler와
  depth 1 QoS를 사용한다.
- 실차 주행 중 필요하지 않은 중간 영상과 디버그 영상 발행을 기본적으로
  끈다.
- 종료 시 추론 스케줄러가 남지 않도록 ROS context와 함께 정리한다.

이 변경으로 기존 통합 인지의 10Hz 출력 제한을 15Hz까지 올렸다. rosbag
재생 시험에서는 인지 약 18.6Hz, RULE shadow 명령 약 19.4Hz를 확인했지만,
현재 통합 실차 실행은 CPU 여유를 확보하기 위해 15Hz로 제한한다. 실제
주행에서는 다음 명령으로 처리율과 프레임 누락 여부를 함께 확인한다.

```bash
ros2 topic hz /perception/canonical_road_image
ros2 topic hz /hybrid/rule_candidate
```

## 4. 통합 주행과 파라미터 입력

카메라, LiDAR, VESC를 연결한 상태에서 다음 명령 하나를 실행한다.

```bash
cd /home/xytron/kookmin_ty/integrated_rule_drive_latest/xycar_ws
set +u
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=7
unset ROS_NAMESPACE

bash src/xycar_map_nav/scripts/run_complete_space_hybrid.sh
```

스크립트가 센서와 제어 노드를 확인한 뒤 아래 값을 차례대로 묻는다. 입력할
때 `m`, `%`, `cm` 같은 단위 문자를 붙이지 말고 **숫자만** 입력한다.
퍼센트와 cm는 정수로 넣어도 되고, 거리와 gain은 소수 입력도 가능하다.
아무 값 없이 Enter를 누르면 표의 기본값을 사용한다.

| 터미널 입력 항목 | 기본값 | 역할 |
| --- | ---: | --- |
| 주행 속도 상한 | 3 | 전체 RULE 속도 상한 |
| 조향각 기반 속도 가감속 | Y | 조향각에 따른 자동 감속 ON/OFF |
| 감속 시작 절대 조향각 | 20 | 이 값 이하에서는 속도 상한 유지 |
| 최저속도 도달 절대 조향각 | 42 | 이 값부터 설정한 코너 속도 유지 |
| 최대 조향 시 속도 | 8 | 최저속도 도달각 이상에서 사용할 command |
| 곡선 Lookahead distance | 0.30 | Pure Pursuit가 앞을 보는 거리 |
| 곡선 Stanley 비율 | 20 | 곡선에서 Stanley 혼합 비율 |
| Pure Pursuit 제어점 X | -0.08 | PP 계산 기준점의 차량 전후 위치 |
| Stanley 제어점 X | 0.16 | 횡오차·방향오차 계산 기준점 |
| 곡선 Stanley gain | 1.15 | 곡선 횡오차 보정 강도 |
| 곡선 Stanley softening | 0.35 | 저속에서 Stanley 과민 반응 완화 |
| 직선 Stanley 비율 | 90 | 직선에서 Stanley 혼합 비율 |
| 직선 Stanley gain | 0.65 | 직선 횡오차 보정 강도 |
| 직선 Stanley softening | 0.65 | 직선 저속 보정 완화 |
| 방향 상충 시 Stanley 비율 | 70 | PP와 Stanley 방향이 반대일 때 비율 |
| 제어 지연 예측 시간 | 0.30 | 차량이 반응할 미래 위치의 예측 시간 |
| 좌측 주행 보정 거리 | 9 | 기준 경로에서 왼쪽으로 이동할 cm |

예를 들어 기본 튜닝을 사용하려면 아래 숫자를 프롬프트 순서대로 입력한다.

```text
3
Y
20
42
8
0.30
20
-0.08
0.16
1.15
0.35
90
0.65
0.65
70
0.30
9
```

곡선 Stanley 비율을 `20`으로 입력하면 Pure Pursuit 비율은 자동으로
`80%`가 된다. 직선 Stanley 비율 `90`은 직선 Pure Pursuit 비율 `10%`로
자동 변환된다. 모든 실행값은 다음 파일에 기록된다.

```text
/tmp/xycar_hybrid_run_config.yaml
```

터미널에 `READY`가 한 번 출력된 뒤에만 조작한다.

- `SPACE`: 주행 시작
- `SPACE`: 다시 누르면 정지
- `Ctrl+C`: 센서와 제어기 전체 종료

## 5. 속도를 올리며 제어 파라미터 조절

앞으로는 같은 구간에서 속도만 `3 -> 6 -> 8 -> 10` 순서로 올리며
파라미터를 조절한다. 한 번에 여러 값을 바꾸지 않고 아래 순서로 한 항목씩
변경하고 rosbag에 실행 설정을 함께 남긴다.

1. 곡선 진입이 늦으면 Lookahead를 조금 줄인다.
2. 곡선 안쪽으로 충분히 들어가지 못하면 Stanley gain 또는 Stanley 비율을
   조금 올린다.
3. 좌우 오실레이션이 생기면 Lookahead, softening 또는 제어 지연 예측
   시간을 조금 올린다.
4. 직선에서 좌우로 흔들리면 직선 Stanley gain과 직선 Stanley 비율을
   조절한다.
5. 곡선 진입과 탈출에서 조향 방향 전환이 늦으면 방향 상충 시 Stanley
   비율을 조절한다.

각 시험에서는 입력한 파라미터, 평균 인지 Hz, 조향 명령, 속도 명령,
차선 이탈 여부와 오실레이션 발생 구간을 기록한다.

## 6. 앞으로 진행할 통합 주행 시험

### 6.1 조향각에 따른 속도 조절

통합 SPACE 게이트에 조향각 속도 조절이 연결되어 있다. 실행 시작 시 ON/OFF,
감속 시작각, 최저속도 도달각과 최대 조향 시 속도를 입력한다. 기본값은
다음과 같다.

- `|조향각| <= 20`: 입력한 속도 상한 유지
- `20 < |조향각| < 42`: 입력 상한에서 command 8까지 선형 감속
- `|조향각| >= 42`: command 8 유지

조향이 다시 0에 가까워지면 입력 속도 상한까지 증가하는지, 곡선 탈출에서
가속이 너무 빠르게 들어가 오실레이션을 만들지 않는지 확인한다.

### 6.2 고속 차량 장애물 회피

고속 주행에서도 YOLO가 차량을 한 프레임 검출하면 회피 상태를 즉시
유지하는지 확인한다. 장애물이 왼쪽이면 현재 기준 경로에서 오른쪽 20cm,
오른쪽이면 왼쪽 20cm로 이동한다. YOLO에서 차량이 사라진 상태가 2초
유지되면 기본 좌측 보정 경로로 복귀해야 한다.

시험 항목은 장애물 좌우 판단, LiDAR 거리, 빈 공간 판단, 회피 중 속도,
회피 방향 고정 여부와 2초 후 경로 복귀다. 짧은 검출 누락 때문에 기본
주행과 회피 주행이 반복 전환되지 않아야 한다.

### 6.3 콘 주행 안정화

콘 검출, 콘 구간 진입, 슬라럼 조향, 콘 구간 탈출과 RULE 복귀가 끊기지
않도록 조정한다. 먼저 command 3에서 반복 성공시킨 뒤 6, 8 순으로
올린다. 콘 탈출 직후 속도 0 또는 후보 명령 timeout이 발생하지 않는지와
RULE 복귀 시 조향이 급격히 튀지 않는지를 중점적으로 확인한다.

최종 목표는 인지 15Hz를 유지하면서 일반 RULE, 차량 회피, 콘 주행 사이의
전환이 한 번씩만 발생하고, 고속에서도 경로 이탈과 조향 오실레이션 없이
완주하는 것이다.
