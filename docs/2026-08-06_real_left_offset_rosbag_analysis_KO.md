# 실차 좌측 15cm 보정 rosbag 분석

## 결론

두 주행 rosbag만으로는 BEV 영점 오차를 직접 측정할 수 없다. 기록된 차선
위치는 이미 `target_left_offset_m`을 적용해 움직인 차량의 **폐루프 평형
결과**이기 때문이다.

대신 2026-07-13~14 임시 트랙에서 차량을 정지시키고 찍은 BEV 보정 화면
`/home/as/Desktop/국민대학교/1783952947775.png`를 찾았다. 이 화면에서
노란선은 `center 0.00m` 가이드와 1cm 이내로 일치한다. 표시된 원본 영상을
복원해 각 homography를 다시 적용하면 다음 결과가 나온다.

| 변환 프로파일 | 정지 노란선의 복원 위치 |
|---|---:|
| 당시 2026-07-14 변환 | `+0.08cm` |
| 2026-07-21 실측 프로파일 | `-3.39cm` |
| 현재 LR-ASPP direct 변환 | `-8.42cm` |

즉 과거 정지 보정에는 15cm 영점 오차가 없었고, 현재 LR-ASPP direct
canonical 변환이 같은 정지 노란선을 오른쪽으로 약 `8.4cm` 이동시키는
것을 재현했다. 현재 좌측 15cm의 상당 부분은 RULE 조향식이나 서보 영점이
아니라 이 변환 차이를 상쇄하고 있을 가능성이 높다. 다만 15cm는 코드상
노란선에서 왼쪽으로 목표 경로를 옮기는 **주행 목표값**이기도 하므로,
15cm 전부를 영점 오차라고 해석해서는 안 된다.

## 분석 데이터

| 세션 | 정적 좌측 보정 | 인지 상한 | 비고 |
|---|---:|---:|---|
| `rule_cone_avoid_run01_20260805_124808` | 0.20m | 7Hz | RULE, RL, 콘, 회피가 섞인 이전 시험 |
| `rule_test_01_20260805_150810` | 0.15m | 10Hz | 현재 기준 RULE+미션 override 시험 |

두 DB의 SQLite 무결성 검사는 모두 `ok`였다. 분석 대상은 다음 조건을
모두 만족하는 샘플로 제한했다.

- SPACE 게이트가 RUN 상태
- 최종 모드가 `RULE`
- 동적 회피 오프셋의 절댓값이 1.5cm 미만
- 속도 command가 2보다 큼
- 조향 command의 절댓값이 5 미만
- RULE heading error의 절댓값이 0.1rad 미만
- RULE 경로가 valid

이 조건은 곡선과 콘·차량 회피가 정적 오프셋 분석에 섞이는 것을 막는다.

## 정지 BEV 기준과 변환 이력

정지 보정 화면의 하단 BEV에서 좌·중·우 가이드는 각각 `+0.40m`,
`0.00m`, `-0.40m`다. 화면 픽셀로 직접 잰 노란선 중심과 0m 가이드의
차이는 약 1cm 미만이다. 같은 화면의 `source` 패널은 1280×1024와 같은
종횡비로 표시되어 있어 원본 크기로 복원한 뒤 변환 프로파일을 비교했다.

당시 프로파일의 원근 사다리꼴 중심은 원본 영상의 위·아래에서 모두
약 `x=726px`이고, 정지 노란선도 약 `x=724px`다. 반면 현재 direct
LR-ASPP 프로파일의 사다리꼴 중심은 위 `x=689px`, 아래 `x=659px`다.
실제 직선 기준보다 각각 약 37px, 67px 왼쪽을 BEV 중앙으로 매핑한다.
그 결과 실제 중앙 노란선이 canonical에서는 오른쪽으로 이동한다.

현재 좌표는 커밋 `b18b570`(2026-07-22, `Add real lane segmentation
canonical pipeline`)에서 direct LR-ASPP 경로에 들어왔다. 현재
`lane_seg_lraspp_canonical_only.launch.py`의 source point는
`(472,494), (906,486), (1272,612), (46,622)`다. 같은 커밋의 기존
`xycar_perception` 실측 프로파일은 이와 다른 2026-07-21 보정 좌표를
사용한다. 즉 두 실차 canonical 경로가 동일한 영점을 공유하지 않는다.

이 비교는 화면에 표시된 원본을 재확대해 수행했으므로 최종 보정값으로
바로 쓰기보다는 원인 위치를 특정하는 증거로 사용해야 한다. 카메라
장착이 이후 바뀌었을 수 있으므로 현재 장착 상태의 정지 원본으로 한 번
더 검증하면 정확한 보정값을 확정할 수 있다.

## 15cm 주행 시험의 폐루프 횡방향 위치

차량 전방 약 `0.30m` 행에서 흰 차선 두 개와 노란 중앙선을 2차 곡선으로
복원한 67개 직선 샘플의 중앙값은 다음과 같다. 차량 좌표의 왼쪽이
양수이고 오른쪽이 음수다.

| 측정값 | 중앙값 | 의미 |
|---|---:|---|
| 흰선 두 개의 중앙 | -0.079m | 도로 중앙을 차량보다 오른쪽 7.9cm로 인식 |
| 노란선 원시 위치 | -0.118m | 노란선을 차량보다 오른쪽 11.8cm로 인식 |
| 노란선 - 흰선 중앙 | -0.031m | 노란선이 흰선 중앙보다 추가로 오른쪽 3.1cm |
| 흰선 중심 간격 | 0.718m | 알려진 0.824m보다 약 12.9% 작음 |

노란선만 더 넓게 사용할 수 있는 직선 샘플에서도 전방 거리별 중앙값은
`-0.115m`(0.16m), `-0.115m`(0.30m), `-0.131m`(0.50m),
`-0.107m`(0.80m)였다. 특정 한 행의 오검출이 아니라 전방 구간 전체의
일관된 횡방향 이동이다.

RULE 진단값으로 같은 계산을 하면 직선 구간의 원시 CTE 중앙값은
`-0.119m`다. 정적 좌측 보정 `+0.150m`를 적용한 뒤 남는 목표 CTE는
약 `+0.031m`다.

```text
원시 노란 경로      -11.9cm
정적 좌측 보정      +15.0cm
제어기가 보는 목표   +3.1cm
```

이 값은 차량이 멈춘 중앙 기준에서 측정한 센서 영점이 아니다. 15cm
목표를 따라간 뒤 차량 좌표에서 관측된 차선 위치다. 따라서 `-11.9cm`를
그대로 homography 오차로 간주하면 안 된다. 정지 화면 재처리에서 직접
재현된 homography 이동량은 약 `-8.4cm`다.

## 20cm 이전 시험과의 교차 확인

같은 필터를 20cm 시험에 적용하면 노란선 중앙값은 약 `-0.152m`, 흰선
중앙은 약 `-0.117m`였다. 보정을 15cm에서 20cm로 5cm 늘렸을 때 차량
좌표에서 관측되는 차선이 오른쪽으로 약 3~4cm 더 이동했다. 정적 목표를
바꾸면 실제 추종 위치도 같은 방향으로 이동한다는 교차 확인이다.

20cm bag은 RL과 여러 재시작 구간이 섞여 있으므로 절대 기준에는 15cm
bag을 사용하고, 20cm bag은 변화 방향 확인에만 사용했다.

## 원인 우선순위

1. **LR-ASPP direct BEV homography 불일치**
   알려진 정지 중앙 프레임을 현재 변환으로 처리하면 노란선이 오른쪽
   약 8.4cm로 이동한다. 기존 실측 프로파일과 direct LR-ASPP가 서로
   다른 source point를 사용하며, 현재 사다리꼴 중심도 직선 소실점에서
   왼쪽으로 치우쳐 있다.
2. **노란선과 흰선의 상대 기하 오차**
   주행 bag에서 노란선은 흰선 중앙보다 추가로 오른쪽 약 3cm에 놓이며,
   흰선 간격도 기준 0.824m보다 작게 복원된다. segmentation 후 canonical
   fit의 클래스별 위치와 횡방향 scale을 함께 재보정해야 한다.
3. **카메라 원점과 제어 원점 차이**
   canonical 전방 거리는 카메라 렌즈 기준인데 RULE 제어와 marker는
   차체 base frame 기준이다. 이 차이는 특히 곡선에서 heading과
   lookahead 오차를 추가할 수 있다.
4. **서보 기계 영점은 bag만으로 판정 불가**
   기록된 `/odom`의 yaw rate는 독립 IMU 측정이 아니라 VESC 드라이버가
   조향 command와 휠베이스로 계산한 값이다. VESC state에도 실제 서보각
   피드백이 없으므로 기계 영점 오차의 크기는 이 두 bag으로 측정할 수
   없다. 다만 차선 위치가 보정 변화에 따라 거의 같은 방향으로 이동한
   점은 인지 좌표 오차가 주원인임을 지지한다.

## 처리율 확인

| 항목 | 20cm/7Hz 시험 | 15cm/10Hz 시험 |
|---|---:|---:|
| 카메라 입력 중앙 rate | 29.56Hz | 30.29Hz |
| lane diagnostics 중앙 rate | 7.16Hz | 10.30Hz |
| RULE 후보 중앙 rate | 7.17Hz | 10.43Hz |
| 최종 게이트 중앙 rate | 19.99Hz | 19.99Hz |
| 전체 callback p50/p95 | 66.3/110.6ms | 61.9/105.8ms |
| 입력 영상 age p50/p95 | 46.8/84.5ms | 44.3/79.9ms |

두 번째 시험에서 RULE은 실제로 약 10Hz에 도달했다. 기록용 압축
canonical 토픽은 별도 압축 노드의 rate 제한 때문에 이보다 낮으므로,
그 토픽 개수만으로 실시간 제어율을 판단하면 안 된다.

## 적용 결과 (2026-08-06)

이 문서의 후속 중앙 정지 bag 검증으로 현재 direct LR-ASPP 변환의 영점
이동이 확인되어 보정 homography를 실행 코드에 적용했다. 중앙 정지 bag에서
물리 노란선은 `-7.88cm`에서 `-0.22cm`, 모델 노란선은 `-6.84cm`에서
`-0.27cm`로 복원됐다. 주행 bag의 paired 비교에서는 경로가 중앙값 기준
왼쪽으로 `6.26cm` 이동했으므로, 과거 물리 주행 위치를 먼저 유지하기 위한
실차 RULE 기본값을 `target_left_offset_m=0.09`로 변경했다.

따라서 아래 절차 중 1~4단계는 rosbag 기준으로 완료됐고, 다음 실차 시험은
새 영점과 `0.09m` 조합에서 저속 shadow/주행 검증부터 진행한다.

## 후속 권장 조치

근본적으로 인지 영점과 주행 목표 오프셋을 분리하기 위해 다음 순서로
마무리한다.

1. 차량 중심을 실제 노란 중앙선 위에 놓고 직선 heading을 고정한다.
2. 중앙, 좌 10cm, 우 10cm 위치에서 원본·canonical mask를 각각 기록한다.
3. 현재 direct LR-ASPP source point를 다시 구해 직선 소실점과 차량
   종축이 canonical의 `y=0`에 놓이도록 한다. 단순 조향 바이어스나
   destination 평행이동만으로 끝내면 거리별 yaw 오차가 남는다.
4. 흰선 중심 간격이 0.824m가 되도록 횡방향 scale을 수정한다.
5. 영점을 고친 뒤 노란선-흰선 사이의 원하는 실제 주행 위치에 맞춰
   `target_left_offset_m`을 별도의 값으로 다시 정한다.
6. shadow mode에서 수정 전/후 canonical과 목표 경로를 A/B 비교한다.
7. 실제 servo horn 또는 외부 yaw 센서로 조향 0 command의 기계 영점을
   별도로 측정한다.

인지 원점 수정 전의 `0.15m` 유지 권고는 위 적용으로 대체됐다. 현재 실차
기본값은 `0.09m`이며, 실차 결과 없이 바로 `0m`로 낮추지는 않는다.
